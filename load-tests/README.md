# K6 Load Tests — InteriorAI Studio

Load testing stack for the InteriorAI Studio backend. Uses **k6** to generate
load, **Prometheus** to store metrics, and **Grafana** to visualize them in
real-time.

---

## Stack

| Tool | Version | Purpose |
|---|---|---|
| [k6](https://k6.io) | 0.54.0 | Load test runner |
| [Prometheus](https://prometheus.io) | 2.53.0 | Metrics storage (receives k6 remote-write) |
| [Grafana](https://grafana.com) | 11.1.0 | Live dashboard (pre-provisioned k6 dashboard) |

---

## Quick Start

### 1. Prerequisites

- Docker Desktop running
- Node.js 18+ (for token generation scripts)
- Your backend running at `http://localhost:5000`

### 2. Create your env file

```bash
cp load-tests/.env.loadtest.example load-tests/.env.loadtest
# Edit load-tests/.env.loadtest with your values
```

### 3. One-time Clerk setup

In [Clerk Dashboard → Configure → Sessions](https://dashboard.clerk.com):
- Set **Session token lifetime** to `7200` seconds (2 hours)

### 4. Generate multi-user tokens

```bash
# From the repo root
source load-tests/.env.loadtest

node load-tests/scripts/generate-tokens.js
```

This creates `fixtures/tokens.json` and prints the `K6_TOKENS=...` value.
Copy it into your `.env.loadtest`.

### 5. Start the observability stack

```bash
cd load-tests
docker compose up -d prometheus grafana
```

Open Grafana: **http://localhost:3001**
(anonymous admin access, k6 dashboard auto-loads)

### 6. Run a test

```bash
cd load-tests

# Smoke test (1 VU, 30s) — sanity check
docker compose run --rm k6 run /scripts/health.js

# Upload test with load preset
docker compose run --rm -e TEST_PRESET=load k6 run /scripts/upload.js

# Full AI pipeline (smoke — safe for real services)
docker compose run --rm k6 run /scripts/editor.js
```

### 7. Run all tests sequentially

```bash
# From repo root
bash load-tests/run-all.sh          # smoke
bash load-tests/run-all.sh load     # load (AI endpoints auto-cap at 2 VUs)
```

### 8. Cleanup test users

```bash
# From repo root
node load-tests/scripts/cleanup-tokens.js
```

## Test Scripts

| Script | Endpoints | Default Preset | Notes |
|---|---|---|---|
| `health.js` | GET `/api/health`, `/api/ready` | smoke | Public, no auth |
| `upload.js` | POST `/api/uploads` | smoke | Requires `K6_TOKENS` |
| `generations.js` | POST `/api/generations`, `/:id/depth` | smoke | Requires `TEST_PROJECT_ID` |
| `editor.js` | 6 POST endpoints | smoke | Requires `TEST_VERSION_ID` |
| `drag.js` | POST `/api/drag/extract` | smoke | Slow — SAM2+LaMa+Depth |

---

## Presets

Override with `TEST_PRESET=<preset>` env var or pass `-e TEST_PRESET=load` to docker compose.

| Preset | VUs | Duration | Use case |
|---|---|---|---|
| `smoke` | 1 | 30s | Sanity check |
| `load` | 5→10 | 5m | Normal traffic |
| `load_ai` | 1→2 | 5m | AI endpoints under load |
| `stress` | 10→50 | 8m | Breaking point |
| `stress_ai` | 1→5 | 8m | AI endpoints stress |
| `soak` | 5 | 20m+ | Memory leak detection |

## Multi-User Token Flow

```
CLERK_SECRET_KEY
      │
      ▼
scripts/generate-tokens.js
  ├── POST /v1/users          → create N test users in Clerk
  ├── POST /v1/sign_in_tokens → one-time sign-in ticket per user
  └── POST <frontend>/v1/client/sign_ins → exchange for session JWT
      │
      ▼
fixtures/tokens.json   (gitignored)
      │
      ▼
K6_TOKENS=jwt1,jwt2,jwt3,...   (set in .env.loadtest)
      │
      ▼
k6 VU[n] uses tokens[(n-1) % pool.length]  → true multi-user simulation
```
